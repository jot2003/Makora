1. OVERVIEW
───────────────────────────────────────────────────────────────────────────────
Makora is a full-stack AI application that records, transcribes, translates,
and provides intelligent suggestions during live interviews and meetings in
real-time. It combines Azure Speech-to-Text, Azure OpenAI (GPT-4o), speaker
diarization, and Retrieval-Augmented Generation (RAG) into a single platform.

GitHub: https://github.com/jot2003/Makora


2. TECH STACK
───────────────────────────────────────────────────────────────────────────────
Frontend:
  - React 19 + TypeScript + Vite 6
  - Tailwind CSS 3.4 + shadcn-style components
  - Zustand 5 (state management)
  - Electron 33 (desktop overlay mode)
  - react-i18next (EN / VI / JA)
  - Recharts (usage dashboard)
  - Framer Motion (animations)

Backend:
  - Python 3.12 + FastAPI + Uvicorn
  - WebSocket (real-time bidirectional communication)
  - SQLAlchemy + SQLite
  - Azure Cognitive Services Speech SDK
  - Azure OpenAI SDK (streaming + non-streaming)
  - PyAudioWPatch (WASAPI loopback audio capture)
  - pyannote.audio 3.x (speaker diarization)
  - FAISS (vector similarity search)
  - pykakasi (Japanese romaji conversion)
  - PyJWT + bcrypt (authentication)

DevOps:
  - Docker (multi-stage builds, nginx reverse proxy)
  - docker-compose (backend + frontend orchestration)
  - GitHub Actions CI (lint, test, build, Docker)
  - Vitest (frontend unit testing)

4. KEY FEATURES
───────────────────────────────────────────────────────────────────────────────
Real-Time Meeting Assistant:
  - Live transcription with Azure Speech SDK (3 recognizer modes)
  - Speaker diarization via pyannote.audio 3.x
  - Conversation stabilization (prefix-locking, display throttling)
  - Final-only translation policy (reduces noise)
  - AI answer suggestions (streaming, with romaji + Vietnamese)
  - Echo cancellation (energy-based gate)
  - Manual "Answer this question" per transcript line
  - Dynamic LLM model switching (env + user DB providers)
  - Adjustable answer length (1-10 sentences) and Japanese level
  - Pre-generated answers with semantic caching (FAISS)

Post-Meeting Intelligence:
  - Structured summary (overview, key topics, decisions, risks, next steps)
  - Action item extraction (task, owner, deadline, priority)
  - Decision tracking with context
  - Meeting timeline with topic segments

Knowledge Copilot (RAG):
  - Chat with meeting transcripts (source citations)
  - Cross-meeting semantic search
  - Auto-indexing after upload (FAISS + text-embedding-3-small)

Authentication & Security:
  - JWT-based auth (register, login, token refresh)
  - OAuth integration (Google, GitHub)
  - WebSocket JWT validation via query string
  - Per-user meeting data isolation (ownership checks)
  - Configurable CORS origins

Internationalization:
  - 3 languages: English, Vietnamese, Japanese
  - Full UI translation (145+ keys per language)
  - Cyclic language switcher (EN → VI → JA)

Desktop Features:
  - Electron overlay (always-on-top captions)
  - Configurable font size, opacity, max history lines

Dashboard & Analytics:
  - LLM token usage tracking per model
  - Cost estimation charts (area, pie, bar)
  - Recent request history

  User              — id, email, username, hashed_password, provider, avatar
  Meeting           — id, user_id (FK), name, mode, language, status
  TranscriptEntry   — meeting_id (FK), speaker, text, romaji, translations
  SessionNote       — meeting_id (FK), category, content
  GlossaryEntry     — meeting_id (FK), jp, reading, vi
  SessionDocument   — meeting_id (FK), filename, category, extracted_text
  UserSettings      — user_id (FK), settings_json
  AIProvider        — user_id (FK), name, provider_type, api_key, endpoint
  LLMUsageLog       — model, prompt/completion tokens, cost, latency
  PreGeneratedAnswer— meeting_id, question_ja, answers, embedding


6. API ENDPOINTS (52 routes)
───────────────────────────────────────────────────────────────────────────────
Auth:       POST /api/auth/register, /login, GET /me, OAuth /google, /github

Intelligence: /api/meetings/{id}/summary, /actions, /timeline, /decisions
Settings:   GET/PUT /api/settings, /providers CRUD, /models
RAG:        POST /api/chat, /search, /meetings/{id}/index
Upload:     POST /api/upload (audio/video → STT → DB)
Usage:      GET /api/usage/summary, /daily, /recent
WebSocket:  WS /ws/meeting (real-time pipeline, JWT-protected)
Health:     GET /health


7. WEBSOCKET PROTOCOL
───────────────────────────────────────────────────────────────────────────────
Connection: ws://host/ws/meeting?token=<JWT>

Client → Server:
  start_meeting, stop_meeting, ping, switch_language, switch_model,
  toggle_suggestions, request_suggestion, manual_answer,
  set_answer_length, set_jp_level, set_max_speakers

Server → Client:
  interim, final, translation, suggestion_start, suggestion_chunk,
  suggestion_done, now_discussing, model_switched, status, pong, error
